سرمقاله

آبان امسال برای انجمن کدنویسی ماهِ برد‌ها بود. درست همان‌طور که قول داده بودیم، مسیر «آموزش Rust از صفر» با درس یازدهم و دوازدهم به پایان رسید و الان، هر عضو انجمن که هر دوازده درس را خوانده باشد، از «Rust چیست؟» تا «سازه‌ها» راه را کامل رفته است. این دوازده درس سه ماه دوید؛ سریع‌تر از آن‌چه در ابتدای مهر تصور می‌کردیم.

اما تمام‌شدن درس‌ها پایان راه نیست؛ شروع است. زبان فقط ابزار است و ابزار وقتی ارزش دارد که چیزی با آن ساخته شود. برای همین چالش آبان را طراحی کردیم: با همان آموخته‌های دوازده درس، یک پروژهٔ کوچک واقعی بساز و در کانال به اشتراک بگذار. جزئیاتش در صفحهٔ چالش این شماره است.

پرونده: چرا Rust از همه‌چیز سخت‌گیرتر است؟

در طول این دوازده درس بارها دیدید که کامپایلر Rust خطا می‌دهد؛ حتی وقتی کد «به نظر» درست می‌آید. مثلاً E0384 وقتی می‌خواهید مقدار متغیر قفل‌شده را عوض کنید، یا E0308 وقتی جعبهٔ عددی را با متن پر می‌کنید. چرا Rust این‌قدر سخت می‌گیرد؟ جوابش سه راز دارد.

۱) سردبیریت (Ownership) — هر چیز یک سردبیر دارد

در Rust هر تکه‌داده یک سردبیر روشن دارد. وقتی سردبیر تمام شود (مثلاً تابع تمام شود)، حافظه خودبه‌خود آزاد می‌شود — بدون زباله‌روب، بدون نشتی حافظه. برای همین Rust هم سریعِ C است و هم امن.

۲) قرض‌دادن (Borrowing) — یا سردبیر باش، یا قرض بگیر

می‌شود داده را به تابع «قرض» داد تا فقط بخواند یا با اجازه عوض کند. Rust حساب‌دار دقیقی است: هم‌زمان نمی‌گذارد دو نفر یکی را عوض کنند. نتیجه؟ همان باگ‌هایی که در زبان‌های دیگر وسط شب گریبان برنامه‌نویس را می‌گیرند، این‌جا موقع کامپایل گرفته می‌شوند.

۳) تغییرناپذیری پیش‌فرض — قفل تا وقتی کلید دادی

یادتان هست درس ۵؟ متغیر پیش‌فرض قفل است و تا ننویسید let mut، تغییر نمی‌کند. این سخت‌گیری باعث می‌شود برنامه‌ها قابل پیش‌بینی و مطمئن‌تر باشند.

پیام اصلی برای شما: وقتی کامپایلر Rust خطا می‌دهد، در حال دفاع از شماست. هر error یک باگ است که قبل از رسیدن به دست کاربر گرفته شده. برنامه‌نویس‌های حرفه‌ای به پیام‌های کامپایلر «دوستِ صمیمی» می‌گویند!

// سخت‌گیری مفید!
let rekord = 12;
rekord = 15; // ❌ error[E0384]: cannot assign twice to immutable variable
let mut emtiaz = 10;
emtiaz = 15; // ✅ چون اجازهٔ تغییر دادیم

درسنامهٔ ویژه: توابع با return

درس ۱۱ برای خیلی از اعضا سخت‌ترین و در عین حال مهم‌ترین درس مسیر بود؛ چون از «نوشتن کد» به «چیدن کد» می‌رسد. این‌جا خلاصهٔ کاربردی‌اش را برای مرور داریم.

صورت مسئله

می‌خواهیم معدل دو نمره را چند بار در برنامه حساب کنیم. اگر هر بار همان تقسیم را بنویسیم، کد شلوغ و خطاخیز می‌شود. راه‌حل: یک تابع، یک بار نوشتن، هر چند بار که لازم باشد صدا زدن.

fn moadele(a: i32, b: i32) -> i32 {
    return (a + b) / 2; // بازگشتِ جواب
}

fn main() {
    println!("{}", moadele(10, 20)); // ۱۵
    println!("{}", moadele(18, 14)); // ۱۶
}
سه نکتهٔ امتحانی
۱) نوع ورودی‌هاپارامترها در پرانتز با نوعشان می‌آیند: a: i32 — مثل معرفی‌کردن مهمان با شناسنامه.
۲) نوع خروجیبعد از -> نوشته می‌شود؛ اگر تابع جوابی نداشته باشد اصلاً نوشته نمی‌شود.
۳) سبک Rustیدر خط آخر می‌شود return و ; را حذف کرد: عبارتِ بدون سمیکالن خودش جواب است.

تمرین این بخش: تابعی به اسم sade_bakhtar بنویسید که یک عدد بگیرد و بگوید اول است یا نه. برای اعداد کوچک، همان راه درس‌های قبل کافی است: حلقه از ۲ تا جذرِ عدد و بررسی باقی‌مانده.

🛠 چالش: کتابخانهٔ کوچک با struct

با آموخته‌های درس ۱۲، یک سازهٔ Ketab بسازید با سه فیلد: esm (نام کتاب)، nevisande (نویسنده) و sale_chap (سال چاپ). سه نمونهٔ کتاب بسازید و در یک حلقهٔ for روی آرایه، همه را با println! قشنگ چاپ کنید.

امتیاز ویژه: تابعی به اسم tozih بنویسید که یک Ketab بگیرد و یک جملهٔ معرفی برگرداند (با return). کدتان را در کانال بفرستید؛ بهترین‌ها در شمارهٔ آذر معرفی می‌شوند.

چهره‌ها: آدا لولیس — اولین برنامه‌نویس تاریخ

حدود دو قرن پیش، وقتی هنوز هیچ کامپیوتری وجود نداشت، دختری در انگلستان با ریاضیات بزرگ شد: آدا لولیس (۱۸۱۵–۱۸۵۲)، دختر شاعر مشهور لرد بایرون. مادرش می‌ترسید آدا مثل پدرش شاعر شود؛ پس ریاضی را جدی گرفت. نتیجه؟ آدا ریاضی‌دان شد و شاعرانه‌ترین برنامه‌نویس تاریخ!

آدا با چارلز ببیج روی «موتور تحلیلی» کار کرد؛ ماشینی مکانیکی که قرار بود محاسبات را خودکار انجام دهد. آدا در یادداشت‌هایش الگوریتمی نوشت برای محاسبهٔ اعداد برنولی با همین ماشین — و همین یادداشت امروز به‌عنوان «اولین برنامهٔ منتشرشدهٔ تاریخ» شناخته می‌شود، سال‌ها پیش از آن‌که اولین کامپیوتر الکترونیکی ساخته شود.

اما نکتهٔ قشنگ‌تر: آدا دید آن‌چه ببیج ساخته فقط برای محاسبهٔ عدد نیست؛ یک ماشینِ همه‌کاره است که می‌تواند موسیقی بسازد و نمادها را ترکیب کند. یعنی او «برنامه‌نویسی» را نه به‌عنوان حساب‌کردن، بلکه به‌عنوان خلق‌کردن دید! زبان برنامه‌نویسی «Ada» به افتخار او نام‌گذاری شده و روز «آدا لولیس» هر سال، زنان دانشمند دنیا را گرامی می‌دارد.
